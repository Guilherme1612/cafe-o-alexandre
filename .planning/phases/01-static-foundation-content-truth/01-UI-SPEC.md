# Phase 1 — UI Design Contract

> Visual and interaction contract for the static Astro foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored CSS custom properties |
| Preset | not applicable |
| Component library | none |
| Icon library | none; use text labels and native links |
| Font | System sans for body (`ui-sans-serif, system-ui, -apple-system, sans-serif`); system serif for display (`ui-serif, Georgia, Cambria, serif`) |

This is an Astro static page with no hydrated islands, UI framework, third-party registry, external font request, or sponsor asset. Keep all tokens in the global stylesheet so later sections inherit the same foundation.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Eyebrow-to-heading gap, icon/text gap when icons are later approved |
| sm | 8px | Label groups, compact metadata, button inline gap |
| md | 16px | Base content padding and default element spacing |
| lg | 24px | Card padding and section sub-group gaps |
| xl | 32px | Hero/content cluster gaps and responsive grid gaps |
| 2xl | 48px | Section separation and hero vertical padding |
| 3xl | 64px | Page-level separation at tablet/desktop widths |

Exceptions: interactive controls use a minimum 48px block size and 44px inline size for comfortable touch access; 1px borders are structural, not spacing tokens.

## Typography

Use only the two weights below (400 regular and 600 semibold). Display type is the only serif treatment; never use all caps for full sentences.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.2 |
| Display | 36px (48px at min-width 768px) | 600 | 1.1 |

Body copy is limited to a comfortable 65ch; hero supporting copy is limited to 38ch. Do not add a display size larger than 48px for this concise page.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Cream `#F7F0E4` | Page background, readable content surfaces, placeholder panel background |
| Secondary (30%) | Charcoal `#272323` | Header/hero band, footer, dark surface panels, primary text on cream |
| Accent (10%) | Burgundy `#762536` and warm gold `#C39A5A` | Burgundy: primary action background, section rules, active emphasis. Gold: eyebrow/rule details and focus ring only on dark surfaces |
| Destructive | `#B42318` | Destructive actions only; none are in Phase 1 |

Accent reserved for: the single primary action style once a verified destination exists, the hero eyebrow rule, section divider/rule, active navigation state, and visible `:focus-visible` ring. Gold must not be used as body text on cream; use charcoal or burgundy for readable copy. Do not use gradients, sponsor logos, ad layouts, textures, or unverified photo assets.

## Copywriting Contract

All business facts and claims come from the shared content object (`src/data/cafe.ts`); the page template may own only structural labels. The approved fixed identity is `Café o Alexandre`. No sponsor name, logo, phone number, menu item, service, opening-hour claim, address, or social handle may enter copy from reference material.

| Element | Copy |
|---------|------|
| Primary CTA | `Call the café` when a verified phone exists; while unknown, show the non-actionable label `Phone number not yet available` |
| Empty state heading | `Café details coming soon` |
| Empty state body | `Verified café information will appear here once it is provided.` |
| Error state | `This detail is unavailable. Verify it with the café before using this action.` |
| Destructive confirmation | None in this phase; no destructive control is rendered |

Placeholder values must remain visibly bracketed and human-readable: `[FULL ADDRESS]`, `[PHONE NUMBER]`, `[WHATSAPP NUMBER]`, `[OPENING HOURS]`, `[SOCIAL LINKS]`, `[CAFÉ DESCRIPTION]`, `[GOOGLE MAPS LINK]`, and `[CAFÉ IMAGES]`. Render an unknown value as plain text in a muted, bordered placeholder treatment. Do not create `href`, `tel:`, WhatsApp, or Maps actions from a placeholder; omit the link entirely until its value is verified.

## Foundation Shell and Visual Hierarchy

- Use one semantic document shell: skip link, `header`, `main#main-content`, named `section` landmarks, and `footer`.
- Render exactly one `h1` for `Café o Alexandre`; subsequent sections use ordered `h2` headings and do not skip levels.
- The first viewport prioritizes identity: dark charcoal hero/header band, a small warm-gold eyebrow, cream display title, one short welcome sentence, and a single clear next-step region. Do not fill the hero with decorative or invented claims.
- Content sections use the dominant cream surface with charcoal body text, a burgundy rule or heading accent, and generous vertical spacing. Reserved secondary dark panels can carry practical content later without changing the hierarchy.
- Keep content centered in a `max-width: 72rem` container. On mobile, use one column and 16px inline gutters; at 768px and above, allow a two-column content grid with 24–32px gaps only when the later content requires it.
- Use 8px corner radii for panels/buttons and a 1px low-contrast border. Avoid heavy shadows; a subtle `0 8px 24px rgb(39 35 35 / 8%)` is the maximum permitted elevation for a raised surface.

## Placeholder and Content-Truth Treatment

- Every unknown business field remains in the shared content object and is rendered by the same field component/path as verified content.
- Placeholders use a muted charcoal-on-cream label, dashed burgundy-tinted border, and the exact bracketed token; add a short visible `Awaiting verified café details` note only where context would otherwise be ambiguous.
- Placeholder blocks are informational text, not disabled buttons or fake links. They must not receive click handlers, pointer cursors, or `aria-disabled` in place of a real destination.
- Keep the page useful if all optional data is missing: identity, structural headings, and the placeholder explanation remain visible with JavaScript disabled.

## Accessibility and Interaction

- Use semantic HTML before ARIA. Add a `Skip to content` link as the first focusable element and keep landmark names unique and descriptive.
- Maintain at least 4.5:1 contrast for normal text and 3:1 for large text. Gold is decorative/focus-only and never carries essential meaning by itself.
- Add a 3px warm-gold `:focus-visible` outline with 2px offset on every actionable element; never remove the browser focus indicator without replacing it.
- Keep all eventual actions as native anchors (`tel:`, WhatsApp URL, Google Maps URL) with descriptive accessible names. Do not use `onclick` pseudo-buttons.
- Use a minimum 48px block size / 44px inline size for controls and preserve a visible text label; no icon-only controls exist in this phase.
- Respect `@media (prefers-reduced-motion: reduce)` by disabling transitions. Otherwise, the only allowed motion is a 120ms color/outline transition on links and buttons; no entrance, scroll, parallax, or autoplay effects.
- Preserve reading order in the DOM and ensure the layout does not require hover, JavaScript, or color perception.

## Responsive Contract

- Mobile-first baseline supports 320px wide viewports without horizontal scrolling. Use a single-column flow, 16px gutters, 48px section padding, and left-aligned text except where a short hero identity lockup is explicitly centered.
- At 768px, increase gutters to 24px, display title to 48px, and permit two-column sections while keeping the hero identity and primary action in the first viewport.
- At 1200px, cap content at 72rem and use 32px gutters/64px section separation. Never stretch text lines beyond 65ch.
- Use CSS media queries and intrinsic sizing only; no client-side viewport detection. Keep all information and placeholder copy readable at 200% zoom.
