<objective>
Establish the smallest reproducible Astro foundation and the single source of truth for unknown café information.

Purpose: VIS-05 and ABOUT-03 require every missing business value to remain visible and non-actionable while preventing invented claims from leaking into later page sections.
Output: A pinned static Astro manifest/configuration, a typed placeholder-rich `cafe` object, and a tiny Node test that protects the content boundary.
</objective>

<prohibitions>
- Do not copy address, phone, hours, social handles, offers, descriptions, map destinations, photos, sponsor names, sponsor logos, or sponsor phone numbers from reference/sponsor material.

</prohibitions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source content → Astro build | Repository authors and future café updates can change values that become public HTML. |
| Package registry → local build | The build trusts the declared Astro package and its lockfile. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `src/data/cafe.ts` | high | mitigate | Keep all public business values in one reviewable object and fail the content-truth test when required placeholders or actionable unknown links drift. |
| T-01-02 | Information disclosure | Published HTML | medium | mitigate | Never import sponsor material or private notes; emit only the approved identity, structural empty-state copy, and explicit placeholders. |
| T-01-03 | Tampering | npm dependency resolution | high | mitigate | Use only the declared Astro 7.x package, commit the npm lockfile, and run install/build from the manifest; no adapter or arbitrary registry package is introduced. |
</threat_model>
